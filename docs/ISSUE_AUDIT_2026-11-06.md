## Confirmed defects found while auditing

### Selected fix: S3 Vectors queries stop early or cannot start

Both stores requested a `query_vectors` paginator. The environment produced by `make install` resolves boto3/botocore **1.40.61**, where `client.can_paginate("query_vectors")` is false and `get_paginator` raises `OperationNotPageableError`. Newer AWS APIs support continuation, but both stores checked `NextToken` instead of the documented **`nextToken`**. This silently discarded later results. Earlier tests used the same incorrect uppercase key.

The fix calls `query_vectors` directly in sync and async stores and forwards a nonempty `nextToken`. This supports a single response on older SDKs and continuation on SDK/service versions exposing it, without changing dependency constraints. A caller still needs an SDK supporting any request fields/features it uses; this change does not add pagination support to an old service model.

Regression coverage includes real SDK clients with Stubber/AioStubber, multiple service pages, empty intermediate pages, client chunk buffering (including a page size larger than top-k), cursor forwarding, top-k limits, one rate-limit acquisition per request, permanent error translation and retry restart. Tests with realistic lowercase tokens reproduced 15 failures before the production fix. The historical pagination issue [#16](https://github.com/codeforstartups/dynavec/issues/16) is closed, so its tracker state alone did not establish correctness.

Sources: [AWS QueryVectors request/response](https://docs.aws.amazon.com/AmazonS3/latest/API/API_S3VectorBuckets_QueryVectors.html), [boto3 query_vectors](https://docs.aws.amazon.com/boto3/latest/reference/services/s3vectors/client/query_vectors.html), and the installed SDK service/paginator model inspected offline.

### Follow-ups reproduced without external services

- **#8:** two CachedEmbedder instances of the same backend class, with different model identities and a shared cache, reuse the first model's vector under the default class-based key. Use explicit distinct `model_key` values as the current workaround; a full fix must encode actual embedding identity.
- **#342:** one Supervisor.run call invokes a configured router **twice**, as shown by a counting router. A stateful router can produce different selections between validation/execution. Reuse the first selected route and add an invocation-count regression.

These findings are resolution work for the relevant issues, not claims that those issues are fixed by this PR. Security-related reproduction details are excluded from this public report in accordance with [SECURITY.md](../SECURITY.md).
